# TASK.md: Комплексный бенчмарк виртуальных машин и контейнеров

**Цель:** Разработать и протестировать набор Python-скриптов для оценки производительности ОС Astra Linux и РЕД ОС в виртуальных машинах QEMU-KVM и Docker-контейнерах.

**Ключевое ограничение:** Избегать установки пакетов из системных репозиториев (там, где это возможно). В приоритете — использование уже готовых инструментов в Docker-образах.

## 1. Общая логика и метрики
Бенчмарк проводится последовательно в два этапа:
1.  **pgbench (тест базы данных):** Прогоняется на всех уровнях фоновой нагрузки CPU (0%, 20%, ..., 100%). Фиксируется метрика **TPS (транзакций в секунду)**.
2.  **linpack (тест CPU):** После pgbench запускается на тех же уровнях нагрузки. Фиксируется метрика **MFLOPS**.
3.  **Сбор метрик:** В каждом тесте утилита `perf` собирает: время выполнения, page-faults, context-switches (если поддерживаются).

## 2. Архитектура и окружение
*   **Архитектуры:** x86 (Intel), ARM (Apple M1), e2k (Эльбрус/VLIW).
*   **Виртуализация:** QEMU-KVM (архитектура хоста == архитектура гостя).
*   **Образы ОС:** Могут быть в формате `.iso` (автоустановка не требуется, предполагается ручное завершение).
*   **Контейнеризация:** Docker.

## 3. Источники инструментов (без системных пакетов)
1.  **pgbench:** Использовать ТОЛЬКО pgbench, встроенный в официальный образ PostgreSQL `postgres:latest` (DockerHub).[reference:0]
    *   *Инициализация тестовых данных:* `docker exec <container> pgbench -i -s 50 -U postgres benchmark`.
    *   *Запуск теста:* `docker exec <container> pgbench -h localhost -U postgres -c 80 -j 8 -T 30 benchmark`.
2.  **linpack:** Использовать эталонный пакет `ereyes01/linpack` с GitHub.[reference:1]
    *   *Предварительная сборка образа:* `git clone` репозитория, `docker build -t linpack ./`.[reference:2]
    *   *Анализ применимости:* Код на `C` (97.4%) и `CMake` (1.2%),[reference:3] можно собрать под любую архитектуру (x86, ARM, e2k) прямо в Docker-контейнере, что исключает зависимость от системных компиляторов.
3.  **Фоновая нагрузка:** `stress-ng` (из официального Docker-образа `alexeiled/stress-ng` или аналога).

## 4. Детали реализации по файлам

### Файл №1: `deploy_vm.py` (Развертывание ВМ)
Скрипт для автоматического создания ВМ из ISO-образа, с драйверами virtio и поддержкой SR-IOV.
*   **Параметры:** `--iso` (путь к ISO), `--name`, `--vcpus`, `--memory`, `--network` (`default`, `bridge:br0`, `sriov:pf_name`).
*   **Логика:** Проверка `virt-install`, создание диска (`qemu-img`), запуск ВМ с virtio и последовательной консолью. Архитектура гостя определяется по хосту (`uname -m`).

### Файл №2: `container_benchmark.py` (Запуск в Docker)
Скрипт для тестирования PostgreSQL и linpack в Docker-контейнерах с нагрузкой на хосте.
*   **Параметры:** `--duration` (по умолчанию 30с), `--pg-container` (имя контейнера с PostgreSQL).
*   **Логика:** Запускает контейнер с PostgreSQL, инициализирует в нем `pgbench`, запускает контейнер с `linpack`. В цикле меняет нагрузку на хосте и запускает тесты последовательно.

### Файл №3: `vm_benchmark.py` (Запуск внутри ВМ)
Скрипт, запускаемый **вручную** внутри гостевой ОС Astra/РЕД с аналогичной логикой.
